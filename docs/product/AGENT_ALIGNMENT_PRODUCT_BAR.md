# Agent alignment product bar

## Product role

PF Remote is a remote-management and mapping layer. It presents many Gateways,
routes, computers, and Shell/Desktop capabilities as stable named targets. The
person uses the native remote-management UI; natural-language work remains in
Codex or another Agent host.

## Visible promise

1. The person sees a clear list of named computers and capabilities.
2. One click opens the selected remote computer with connection details hidden.
3. One explicit Settings action makes PF Remote available to the external Agent
   without command-line setup, and can remove only the PF Remote-owned entry.
4. One computer action copies or sends a safe, exact target context to the Agent.
5. The Agent resolves the same immutable Device and Capability through PF
   Remote, even if an alias or route changes.
6. MCP, Skill, CLI, or an equivalent Agent interface can inspect and operate
   authorized targets and return structured results.

## Product-manager acceptance gate

Do not request project-manager experience for backend contracts, CLI-only
flows, a single-device connectivity proof, unfinished UI, or an embedded chat
mockup. Continue development until the remote manager is polished and at least
one complete alignment journey works:

**select a computer in PF Remote → hand it to Codex → Codex identifies and
controls that exact computer through PF Remote.**

Before every experience request, state the specific improvement over the
existing remote-control workflow and the user-level judgment being requested.
